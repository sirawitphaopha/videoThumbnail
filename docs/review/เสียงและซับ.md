### 3. 🟠 เปิด Loudness normalize แล้วเสียงที่แปลงออกมาเป็น 192 kHz
- **ที่** `src-tauri/src/encode.rs:131-136` (`loudnorm=I=-23:TP=-1` ต่อด้วย `aresample` เฉพาะเมื่อตั้งอัตราสุ่มเอง) · การ์ดบอก "ไม่เปลี่ยนขนาดไฟล์" `src/components/CodecPanel.tsx:329` · เทสเช็กแค่ข้อความคำสั่ง `encode.rs:626-635` · เทสแปลงจริง `real_encodes` `:723-792` ไม่มีเคสเปิด loudnorm · ตัวตรวจ `check-merge.mjs` `check-convert.mjs` ไม่มีคำว่า loudnorm
- **เกิดยังไง** ตัวกรอง loudnorm ของ ffmpeg แบบผ่านเดียว (ไม่ใส่ค่าที่วัดไว้ = โหมด dynamic) บังคับอัตราสุ่มขาเข้าและขาออกเป็น 192000 Hz (af_loudnorm.c `query_formats`) · Sample rate ค่าตั้งต้นคือ "ตามต้นฉบับ" จึงไม่มี aresample ต่อท้าย
  1. แผงตั้งค่าเสียง FLAC มาตรฐาน · Loudness normalize เปิด · Sample rate ตามต้นฉบับ (48 kHz)
  2. ffmpeg ส่ง WAV 192 kHz ทางท่อ → flac ได้ไฟล์ 192 kHz
- **ผลที่ผู้ใช้เจอ** FLAC WavPack Monkey's Audio TAK ใหญ่ราว 4 เท่าของที่แผงบอก อัตราสุ่มในไฟล์ใหม่เปลี่ยนจาก 48 เป็น 192 kHz · ffmpeg AAC ได้ 96 kHz · fdkaac รับ 192 kHz ไม่ได้ แปลงล้ม · เช็กที่ว่าง (`merge.rs:519-533` `convert.rs:336-347`) คิดจากอัตราเดิม ที่ว่างอาจหมดกลางทาง (ไฟล์ทำค้างถูกลบ ไฟล์เดิมไม่ถูกแตะ)
- **ทางแก้ที่เสนอ** ต่อ `aresample=<อัตราของต้นทาง>` หลัง loudnorm ทุกครั้ง (ส่งอัตราของต้นทางเข้า `build` แบบเดียวกับ `src_bits`) · เพิ่มเทสแปลงจริงที่เปิด loudnorm แล้วเช็ก sample_rate ของไฟล์ที่ได้เท่าต้นทาง
- ⚠️ ยืนยันด้วยการลอง แปลงแทร็ก 48 kHz เป็น FLAC เปิด loudnorm แล้ว ffprobe ดู sample_rate
- **ผลที่แคลร์ตรวจ** จริง ยืนยันด้วยการลอง · ffmpeg loudnorm กับเสียง 48 kHz ได้ 192000 · ต่อ aresample=48000 ได้ 48000 · **แก้แล้ว** ต่อ aresample อัตราของต้นทางหลัง loudnorm ทุกครั้งที่ไม่ได้ตั้งอัตราเอง (`src_rate` ใน EncodeSpec คนเรียกตั้ง หน้าจอส่งอัตราไปตัวสร้างคำสั่งตัวอย่าง) · เทสใหม่ `loudnorm_keeps_source_rate` WAV 44.1 kHz ได้ 44100
