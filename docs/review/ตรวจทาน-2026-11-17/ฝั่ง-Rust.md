## R3 ปานกลาง · ตัวอักษรที่กว้างเกิน 1920 หรือสูงเกิน 1080 จุดที่สอนเข้าฐาน nOCR ทำให้เปิดฐานครั้งต่อไปได้ฐานว่าง แล้วบันทึกทับจนตัวที่สอนไว้หายหมด

**ผิดอะไร** ตัวที่สอนมีขนาดเท่าชิ้นในภาพ (หรือกรอบรวมของตัวขยายจับ) ไม่มีเพดาน · ตอนบันทึกเขียนแบบสองไบต์ได้ แต่ตอนเปิด `NChar::read` คืน None สำหรับตัวที่ใหญ่เกิน แล้ว `load` หยุดทั้งไฟล์ · ตัวใหม่อยู่หน้าสุดของรายการ จึงเป็นตัวแรกในไฟล์ · Subtitle Edit มีหลุมเดียวกัน (`NOcrChar.cs` บรรทัด 146 กับ `NOcrDb.cs` บรรทัด 189) แต่ชั้นหนังเปิดซับ 4K แล้วสอนตัวขยายจับได้ถึง 11 ชิ้น

**เกิดได้ยังไง** ซับ PGS 3840 × 2160 ที่ตัวอักษรติดเส้นใต้ยาวทั้งบรรทัด (แยกเป็นชิ้นเดียวกว้างเกิน 1920) หรือกดขยายกรอบรวมหลายชิ้นจนกว้างเกิน 1920 → กดจำตัวนี้ → บันทึกสำเร็จ → เปิดโปรแกรมใหม่ ฐานนี้ว่าง (ไม่มีข้อความผิดพลาด) → สอนตัวถัดไปหนึ่งตัว → `save` เขียนฐานที่มีตัวเดียวทับ ฐานเดิมไปอยู่ถังขยะ (R2) ผู้ใช้ไม่รู้ว่าต้องไปกู้ · ความน่าจะเกิด **ไม่แน่ใจ** กลไกยืนยันจากโค้ดแล้ว

## ที่ตรวจแล้วไม่เจอปัญหา (ไว้ให้รอบหน้าไม่ต้องไล่ซ้ำ)
- `session()` คืนล็อกที่เสียจาก panic ด้วย `into_inner` ล็อกของงานไม่ค้างถาวร
- `remove_items` เลื่อนลำดับ ข้อความ ตัวที่ข้าม คำตอบใช้ครั้งเดียว และประวัติครบ ล้างตัวที่รอสอนกับหน้าต่างตรวจบรรทัด
- ตัวอ่าน VobSub (`parse_spu` `decode_indices` `spu_at`) มีตัวกันวนไม่จบและเช็กขอบทุกจุด กรอบกลับด้านคืน None ความยาวเติมถึงสุดแถวไม่ทำให้วนซ้ำ
- `parse_sup` เช็กความยาวส่วนก่อนอ่านทุกจุด ต่อชิ้นข้อมูลของวัตถุถูกตำแหน่ง (ชิ้นแรกเริ่มไบต์ 11 ชิ้นต่อเริ่มไบต์ 4)
- `run_tool_timeout` อ่านสองท่อคนละเธรด มีเวลาหมด ผูกกับโปรแกรม Tesseract ใช้ตัวนี้ทุกครั้ง
- ส่งออก SRT ASS ผ่าน `subdoc::save` แบบ new และชนิดของ SeConv ลอกเป็นไฟล์ชั่วคราวข้างที่เก็บแล้ว `move_no_replace` ข้ามไดรฟ์ได้ ลบโฟลเดอร์ `ocrexp-*` ทุกทาง
- ชื่อฐานกันอักษรที่พาออกนอกโฟลเดอร์ (`check_name`) ฐานที่แนบมาไม่ถูกเขียนทับ
- ตัวจับคู่ nOCR Binary OCR และตัวสอนเอง ดัชนีของชิ้น ภาพ และเส้นเช็กขอบครบในจุดที่อ่าน (`count_errors` `alike_*` `group_piece` `following`)
- ตัวตัดบรรทัดเองย้ายแท็กปิดกลับท้ายบรรทัดบนด้วยตำแหน่งไบต์ที่ถูก (`ocrbreak.rs:464-471`) ข้อความไทยไม่มีจุดตัดคืนข้อความเดิม
