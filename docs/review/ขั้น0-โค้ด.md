### 6. 🟡 สิทธิ์ `core:window:allow-destroy` เปิดทางให้หน้าจอปิดโปรแกรมข้ามตัวกันปิดฝั่ง Rust
- ไฟล์: `src-tauri/capabilities/default.json:12` (และ `:7` `core:default`)
- ผิดตรงไหน: TECH-REVIEW ข้อ 7 ตั้งใจ "กันปิดจากฝั่ง Rust" ตอนงานยังรัน แต่ `destroy()` ไม่ผ่านเหตุการณ์ CloseRequested เลย ถ้าหน้าจอเรียก `getCurrentWindow().destroy()` (บั๊ก หรือปุ่ม "ปิดเลย" ที่เขียนพลาด) หน้าต่างสุดท้ายหายทันที โปรแกรมปิดตาม งานที่ค้างอยู่ถูกตัดกลางคัน
- เกิดอะไรได้ (ขั้นหลัง): กำลังเปลี่ยนชื่อไฟล์เดิมเป็นสำรอง แล้วย้ายไฟล์ .partial เข้าที่ → โปรแกรมโดนปิดระหว่างสองขั้นนี้ → ชื่อไฟล์หนังเดิมหายไปจากที่เดิม เหลือแต่ .partial กับสำรองที่ผู้ใช้หาไม่เจอ
- ทางแก้: ใส่ตัวกันที่ `RunEvent::ExitRequested` ด้วย (`api.prevent_exit()` ตอนมีงาน) ไม่ใช่แค่ `WindowEvent::CloseRequested` · หรือไม่ให้สิทธิ์ destroy แล้วให้ปุ่มปิดเรียกคำสั่ง Rust ที่เช็กงานก่อนปิดเอง · ตอนนี้ยังไม่มีงาน จึงยังไม่พัง แต่ต้องตัดสินก่อนขั้นที่เขียนไฟล์
- เพิ่มเติม: `core:default` ให้มากกว่าที่ใช้ (เมนู ถาด `core:image:allow-from-path` ที่อ่านรูปจากที่อยู่ใดก็ได้ `core:tray:allow-set-temp-dir-path`) · ตามคำอธิบายในไฟล์เองที่ว่าไม่เปิดสิทธิ์เกินให้หน้าจอ ควรเปลี่ยนเป็นรายการเฉพาะ `core:event:default` `core:window:default` `core:app:default` `core:path:default` `core:webview:default`
