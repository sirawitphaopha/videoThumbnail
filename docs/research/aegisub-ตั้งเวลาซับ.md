## 1. เส้นแบ่งฉากบนคลื่นเสียงคือเส้น keyframe ไม่ใช่การฟังเสียง
- เส้นที่พี่กันเห็นบนภาพคลื่นเสียงของ Aegisub คือ **keyframe ของวิดีโอ** (`AudioMarkerProviderKeyframes`) วาดเป็นเส้นตั้งสีเดียวตลอดความสูง ไม่มีหัวลูกศร
- keyframe คือเฟรมที่ตัวเข้ารหัสวิดีโอเก็บเป็นภาพเต็ม ตัวเข้ารหัสอย่าง x264 x265 ตั้ง keyframe ตรงจุดตัดฉากเองอัตโนมัติ (scenecut) เส้นจึงตรงกับจุดเปลี่ยนฉากเกือบทุกครั้ง แต่ก็มี keyframe ที่ตั้งตามรอบเวลาปนอยู่ด้วย (เช่นทุก 10 วินาทีในฉากยาวที่ไม่มีการตัด)
- Aegisub ได้ keyframe สองทาง
  - อ่านจากวิดีโอตอนเปิด ผ่านดัชนีของ FFMS2 ไล่ทุกเฟรมแล้วเก็บเลขเฟรมที่เป็น keyframe (`video_provider_ffmpegsource.cpp` บรรทัด 262 ถึง 276)
  - โหลดไฟล์ keyframe ที่ทำไว้ก่อน รับ 6 แบบ คือ Aegisub v1 · ไฟล์สถิติ XviD 2-pass · ffmpeg และ avconv แบบ xvid · DivX · ไฟล์สถิติ x264 · WWXD (qpfile)
- คนทำซับมืออาชีพไม่ใช้ keyframe ที่ติดมากับไฟล์ตรง ๆ แต่สร้างไฟล์ keyframe ใหม่ด้วยตัวตรวจฉากอย่าง SCXvid หรือ WWXD ซึ่งถอดภาพทุกเฟรมแล้วหาจุดที่ภาพเปลี่ยนจริง แล้วโหลดเข้า Aegisub ได้เส้นที่ตรงฉากกว่า
- Aegisub ไม่ได้ตรวจฉากจากเสียงเลย

## 2. ลากเวลาบนคลื่นเสียง
บรรทัดที่เลือกอยู่มีขอบซ้าย (เวลาเริ่ม) กับขอบขวา (เวลาจบ) เป็นเส้นสองเส้น สีต่างกัน มีหัวเล็ก ๆ ชี้เข้าหากัน

| ทำอะไร | ผล |
|---|---|
| เลื่อนเมาส์เข้าใกล้ขอบไม่เกิน 8 จุด | เคอร์เซอร์เปลี่ยนเป็นลูกศรซ้ายขวา บอกว่าลากได้ |
| กดซ้ายใกล้ขอบแล้วลาก | ลากขอบนั้น · ถ้ากดใกล้ขอบซ้าย ขอบซ้ายกระโดดมาที่จุดกดทันที |
| กดซ้ายไกลจากขอบทั้งสอง | ขอบซ้ายกระโดดมาที่จุดกด แล้วถ้าลากต่อ ขอบขวาตามเมาส์ คือลากสร้างช่วงใหม่ได้ในจังหวะเดียว (ค่า Drag Timing เปิดเป็นค่าตั้งต้น) |
| กดขวาตรงไหนก็ได้ | ขอบขวา (เวลาจบ) มาที่จุดนั้น ลากต่อได้ |
| Ctrl กับลากขอบ | ลากขอบนั้นพร้อมขอบของบรรทัดอื่นที่อยู่ตำแหน่งเดียวกัน บรรทัดที่ต่อกันจึงยังต่อกัน |
| Alt กับลาก | เลื่อนทั้งบรรทัด ความยาวเท่าเดิม |
| Shift ระหว่างลาก | สลับเปิดปิดการดูดติดเส้นชั่วคราว |
| กดปุ่มกลางเมาส์ | พาภาพวิดีโอไปที่เวลานั้น |
| ปล่อยเมาส์ใกล้ขอบภาพไม่เกินร้อยละ 5 ของความกว้าง | ภาพคลื่นเสียงเลื่อนไปทางนั้นหนึ่งในสามของจอ |
| ลากเลยขอบซ้ายข้ามขอบขวา | สลับบทบาทให้เอง ขอบที่อยู่ซ้ายเป็นเวลาเริ่มเสมอ (`CheckMarkers`) |

- **ดูดติดเส้น** ระยะ 8 จุดบนจอ แปลงเป็นมิลลิวินาทีตามระดับซูม ดูดเข้าหาเส้นที่ใกล้ที่สุดในสามชนิด คือ เส้น keyframe · ขอบเฟรมวิดีโอที่ดูอยู่ · ขอบของบรรทัดอื่น (`SnapMarkers` บรรทัด 830 ถึง 923)
- ทุกการลากจดเป็นการแก้ที่ยังไม่บันทึก กด Enter หรือ G เพื่อยืนยันเวลา (ค่า Auto Commit ปิดเป็นค่าตั้งต้น) เลิกทำได้
- กดไปบรรทัดถัดไปแบบสร้างใหม่ บรรทัดใหม่เริ่มที่เวลาจบของบรรทัดก่อน ยาว 3 วินาที

## 3. ของอื่นที่วาดบนคลื่นเสียง
- ช่วงเวลาของบรรทัดที่เลือกระบายสีเข้ม บรรทัดอื่นทั้งไฟล์ระบายสีจางพร้อมเส้นขอบสีเทา (ค่าตั้งต้นแสดงทุกบรรทัด) บรรทัดที่เลือกไว้หลายบรรทัดระบายอีกสี
- เส้นตำแหน่งวิดีโอที่ดูอยู่ พร้อมแถบบาง ๆ บอกช่วงของเฟรมปัจจุบันกับเฟรมก่อนหน้า
- เส้นประทุกหนึ่งวินาที
- เส้นเคอร์เซอร์ตามเมาส์ พร้อมเวลา
- ภาพเป็นได้ทั้งรูปคลื่นและภาพความถี่ (spectrum) แบบที่ตัวดูซับของเรามีอยู่แล้ว

## 4. ปรับเวลาทั้งไฟล์ (Timing Post-Processor)
หน้าต่างเดียวทำสี่อย่างกับทุกบรรทัดหรือเฉพาะบรรทัดที่เลือก ค่าตั้งต้นตาม default_config.json

| อย่าง | ค่าตั้งต้น | ทำอะไร |
|---|---|---|
| เผื่อหน้า (lead-in) | 100 ms | เลื่อนเวลาเริ่มเร็วขึ้น แต่ไม่ล้ำบรรทัดก่อนที่ไม่ได้ซ้อนกันอยู่แล้ว |
| เผื่อท้าย (lead-out) | 350 ms | เลื่อนเวลาจบช้าลง แต่ไม่ล้ำบรรทัดถัดไป |
| ต่อบรรทัดที่ใกล้กัน | ห่างไม่เกิน 300 ms หรือซ้อนไม่เกิน 50 ms | ให้จบกับเริ่มเป็นเวลาเดียวกัน จุดต่ออยู่ที่ร้อยละ 90 ของช่องว่าง (ค่อนไปทางยืดบรรทัดแรก) |
| ดูดเข้า keyframe | เริ่มก่อน 200 หลัง 150 · จบก่อน 200 หลัง 250 ms | ถ้าเวลาเริ่มหรือจบห่าง keyframe ที่ใกล้สุดไม่เกินเกณฑ์ ย้ายไปตรง keyframe เวลาจบย้ายไปที่เฟรมก่อน keyframe หนึ่งเฟรม ซับจึงไม่ค้างข้ามฉาก |

## 6. ทำในโปรแกรมเรายังไง
- **keyframe** ใช้ ffprobe ที่แนบมากับโปรแกรมอยู่แล้ว ถอดเฉพาะ keyframe
  `ffprobe -v error -select_streams v:0 -skip_frame nokey -show_entries frame=pts_time -of csv=p=0 <ไฟล์>`
  ลองกับไฟล์ทดสอบ ดาวเหนือ (2023).mkv ยาว 20 วินาที ได้ 0 กับ 10.417 วินาที ใช้ 0.25 วินาที · หนังยาวต้องลองจริงว่ากี่วินาที เก็บผลไว้ต่อไฟล์แบบที่หน้ากราฟเสียงเก็บ ไม่ต้องถอดซ้ำ
- **จุดเปลี่ยนฉากจริง** แบบ SCXvid ใช้ตัวกรอง scdet ของ ffmpeg ที่แนบอยู่แล้ว (เช็กแล้วมีตัวกรอง scdet กับ select)
  `ffmpeg -i <ไฟล์> -an -sn -vf "scale=320:-1,scdet=threshold=10:sc_pass=1,metadata=print:file=-" -f null -`
  ต้องถอดภาพทุกเฟรม หนังสองชั่วโมงคาดว่าใช้หลายนาที ควรเป็นปุ่มกดเองพร้อมแถบความคืบหน้า ไม่ทำตอนเปิดไฟล์ · ไฟล์ทดสอบเป็นภาพแถบสีไม่มีฉากตัด จึงไม่เจอจุดเปลี่ยน ยังไม่ได้ลองกับหนังจริง
- **ภาพคลื่นเสียง** ตัวดูซับมีคลื่นเสียงจาก sub_wave กับภาพความถี่อยู่แล้ว เพิ่มขอบเวลาที่ลากได้ ระยะจับ 8 จุด ดูดติดเส้น keyframe กับขอบบรรทัดอื่น Shift สลับการดูด Alt เลื่อนทั้งบรรทัด และคีย์ลัดตามตารางข้อ 5
- **ปรับเวลาทั้งไฟล์** เพิ่มเป็นปุ่มในแถบเครื่องมือหน้าแก้ซับ ข้างเลื่อนเวลาทั้งไฟล์ ใช้ค่าตั้งต้นของ Aegisub ข้อ 4
- ทั้งหมดใช้กับมอคอัปหน้าแก้ซับแบบที่พี่กันเลือก (docs/mockups/sub-editor-pick.html)

## 7. ช่องขั้นสูงในหน้าแก้บรรทัด ทำอะไรบ้าง (พี่กันถาม *"อันนี้มีไว้ทำอะไรมั่ง ไปดูใน code ของโปรแกรม"*)
อ่านจาก `src/subs_edit_box.cpp` `src/command/edit.cpp` `src/grid_column.cpp` `src/dialog_selection.cpp` `automation/autoload/kara-templater.lua` · ทั้งห้าอย่างเป็นของไฟล์ ASS ไฟล์ SRT ไม่มี

| ช่อง | ทำอะไร |
|---|---|
| ตัวละคร (Actor) | ชื่อคนพูดของบรรทัดนั้น โปรแกรมเล่นไม่แสดง คำอธิบายในซอร์สเขียนเองว่าไว้อ้างอิงอย่างเดียว ใช้จริงสามทาง คือเปิดเป็นคอลัมน์ในตาราง เลือกบรรทัดทั้งหมดของคนพูดคนเดียวกันในหน้าต่างเลือกบรรทัด และค้นแทนที่เฉพาะช่องนี้ |
| เอฟเฟกต์ (Effect) | ช่องเก็บข้อมูลเสริมของบรรทัด ใช้หลัก ๆ กับซับคาราโอเกะ ตัวสร้างคาราโอเกะของ Aegisub (Karaoke Templater) อ่านคำว่า template code fx ในช่องนี้ เพื่อรู้ว่าบรรทัดไหนเป็นแม่แบบ บรรทัดไหนเป็นผลที่สร้าง · โปรแกรมเล่นบางตัวรองรับเอฟเฟกต์เก่าของ SSA อย่างตัวหนังสือวิ่ง (Banner Scroll) ด้วย |
| เลเยอร์ (Layer) | ลำดับชั้นเวลาซับขึ้นพร้อมกันและซ้อนกัน เลขมากวาดทับเลขน้อย ใช้กับซับตกแต่ง เช่นตัวหนังสือมีกรอบหลายชั้น หรือป้ายในฉาก · ซับพูดธรรมดาเป็น 0 ทุกบรรทัด |
| ระยะขอบสามช่อง (Margin L R V) | ขยับตำแหน่งของบรรทัดนั้นจากขอบซ้าย ขอบขวา และขอบบนหรือล่าง ใส่ 0 คือใช้ระยะตามสไตล์ ใช้ตอนบรรทัดเดียวต้องหลบของบนจอ เช่นป้ายชื่อรายการ โดยไม่ต้องสร้างสไตล์ใหม่ |
| ปุ่ม fn | เปิดหน้าต่างเลือกฟอนต์ของ Windows แล้วใส่แท็ก \fn ชื่อฟอนต์ \fs ขนาด \b \i \u ตรงข้อความที่เลือก ให้บรรทัดนั้นใช้ฟอนต์ต่างจากสไตล์ |

แคลร์แนะนำให้ยังไม่ใส่ห้าอย่างนี้ในรอบแรก เพราะเป็นงานซับตกแต่งกับคาราโอเกะ ซับหนังทั่วไปไม่ได้ใช้ · ถ้าเปิดไฟล์ ASS ที่มีค่าเหล่านี้อยู่ โปรแกรมต้องเก็บค่าเดิมไว้ครบตอนบันทึก ห้ามล้างทิ้ง · ทำเป็นส่วนขั้นสูงที่พับไว้ทีหลังได้

## 8. Aegisub เล่นวิดีโอยังไง (พี่กันสั่ง *"อ่านใน โปรแกรม ว่าเขาเล่นวิดีโอยังไง"* ใช้ตอนทำระบบดูวิดีโอในแอป)
อ่านจาก `src/video_controller.cpp` `src/async_video_provider.cpp` `src/video_provider_ffmpegsource.cpp` `src/video_out_gl.cpp`
- **เสียงเป็นตัวนำ ภาพตาม** กดเล่นแล้วสั่งตัวเล่นเสียงเล่นจากเวลาเริ่ม แล้วตั้งนาฬิกาทุก 10 ms คิดว่าผ่านไปกี่มิลลิวินาทีแล้ว แปลงเป็นเลขเฟรม ถ้าเฟรมเปลี่ยนก็ขอภาพเฟรมนั้น (`OnPlayTimer` บรรทัด 178 ถึง 190) ไม่ได้เล่นเป็นสตรีมวิดีโอ แต่ขอภาพทีละเฟรมเร็ว ๆ
- **ขอภาพไม่รอคิว** คำขอทุกครั้งได้เลขรุ่น งานเบื้องหลังถอดภาพเฉพาะคำขอล่าสุด คำขอเก่าที่ยังไม่ได้ทำถูกข้ามทิ้ง (`ProcAsync` เช็ก req_version) เครื่องช้าภาพจึงข้ามเฟรมแทนที่จะช้าลงเรื่อย ๆ
- **ถอดภาพด้วย FFMS2** ซึ่งสร้างดัชนีทุกเฟรมตอนเปิดไฟล์ ได้เลขเฟรม เวลา และ keyframe ครบ กระโดดไปเฟรมไหนก็ได้แม่นทุกเฟรม
- **วาดซับทับภาพด้วย libass** ตัวเดียวกับที่โปรแกรมเล่นหนังส่วนใหญ่ใช้ ภาพกับซับรวมกันแล้วค่อยส่งขึ้นจอ วาดใหม่เฉพาะตอนเฟรมเปลี่ยนหรือบรรทัดที่เห็นอยู่ถูกแก้ (`NeedUpdate`)
- **ขึ้นจอด้วย OpenGL** ภาพเป็นพื้นผิว (texture) ย่อขยายตามหน้าต่าง
- **เล่นบรรทัด** เล่นเสียงช่วงของบรรทัด ภาพเริ่มที่เฟรมแรกของบรรทัดและหยุดที่เฟรมหลังจบ · **เดินหน้าถอยหลังทีละเฟรม** เล่นเสียงสั้น ๆ ของเฟรมนั้นด้วยถ้าเปิดค่าไว้ · **เปลี่ยนบรรทัด** ภาพกระโดดไปเวลาเริ่มของบรรทัดใหม่ (ค่า Subtitle Sync)
- ในโปรแกรมเรา หน้าจอเป็น WebView2 ทำแบบเดียวกันได้สองทาง ทางแรก ffmpeg ถอดภาพทีละเฟรมส่งมาแบบที่ตัวดูซับทำอยู่ เร็วพอสำหรับเดินทีละเฟรมแต่ไม่พอเล่นต่อเนื่อง ทางที่สอง แปลงเป็นสตรีมที่เบราว์เซอร์เล่นได้แล้วใช้ตัวเล่นของเบราว์เซอร์ คู่กับ libass รุ่นที่รันในเบราว์เซอร์ (JASSUB) วาดซับ · ต้องลองจริงตอนทำระบบดูวิดีโอ
