# แผนจัดโครงไฟล์ตามความหมาย (BUGS ข้อ 155) · 24 พ.ย. 2569

## ที่มา
- แบ่งไฟล์รอบคลาวด์ (BUGS ข้อ 153) ย้ายโค้ดอย่างเดียว ไม่เปลี่ยนเนื้อ
- ผลคือ ไฟล์ Rust ไม่เกิน 600 บรรทัดครบ แต่หน้าจอสี่ไฟล์ยังเกิน
- สี่ไฟล์นั้นเป็นหน้าจอที่เขียนเป็นฟังก์ชันก้อนเดียว ตัดแล้วย้ายไม่ได้ ต้องจัดโครงใหม่
- พี่กันสั่ง 24 พ.ย. 2569
  - *"อนาคตมันจะต้องมีระบบที่เเยกไฟล์เล็กๆได้เองเพื่อความว่ายในการแก้"*
  - *"ไม่ใช่เเค่ตัดเหลือ 600 เเต่ไฟล์ไหนควรเล็กกว่านั้นก็ทำได้ถ้าระบบมันเอื้อต่อการเเบ่งไฟล์"*
  - *"เราหมายถึงให้เธอประเมินทุกไฟล์ ว่าควรเเบ่งย่อยไหม"*
- เป้าหมาย
  - แก้ส่วนไหนของหน้า เปิดไฟล์ของส่วนนั้นไฟล์เดียวที่สั้น
  - หน้าตาและการทำงานเหมือนเดิมทุกจุด
  - ของใหม่ในอนาคตมีที่ลงตามแบบ ไม่ไปกองรวมในก้อนเดียวอีก

## คำเคาะที่ใช้ทำ (รายละเอียดเต็มอยู่ BUGS ข้อ 155)
- ประเมินทุกไฟล์โค้ด ทั้ง Rust และหน้าจอ ไม่รวมตัวตรวจใน `scripts/` (ข้อ 153 เคาะว่าไม่แบ่งตัวตรวจ)
- แบ่งตามความหมาย ไม่ใช่ตามตัวเลข · เป้าไฟล์ละราว 150 ถึง 300 บรรทัด · ไม่ซอยจนเหลือไฟล์ละไม่กี่สิบบรรทัด
- ตัวเตือนฟังก์ชันยาว เกิน 200 บรรทัดเตือนอย่างเดียว ไม่กัน commit
  - พี่กันสั่ง *"ไม่ต้องบังคับขนาดนั้น เพราะยังไงก็เเก้ไปก่อน เดี๋ยวถึงวันนึงที่แก้ไปเยอะ เราก็จะมาสั่งให้เธอเเบ่งไฟล์อีกรอบ"*
  - เพดานไฟล์ 600 บรรทัดเดิมยังกัน commit เหมือนเดิม
- ไม่ใช้ plan mode ตามที่แคลร์เสนอ แต่พี่กันเปิดเอง จึงเขียนแผนนี้ให้เคาะ
- ประเมินแล้วทำต่อตามขั้นที่เสนอเลย ไม่หยุดรอเคาะ (พี่กันสั่ง *"ก็เเบ่งขั้นตามที่จะเสนอเลย"*)
- รุ่นและการ push
  - commit ทุกขั้น
  - แบ่งงานครึ่งหนึ่ง push เป็นรุ่น 0.10.4 อีกครึ่ง push เป็นรุ่น 0.10.5
  - พี่กันยืนยัน *"0.10.2 กับ 0.10.3 ไปเเล้วนี่"* จึงไม่ข้ามรุ่น
- ลำดับตอนท้าย (พี่กันสั่ง)
  - ทำครบแล้ว รันผู้ช่วยตรวจทาน 3 ตัว แก้ตามที่เจอ
  - สร้างตัวติดตั้ง แล้ว push
  - ระหว่างทางยังไม่รัน cargo test ชุดใหญ่
  - เทสใหญ่ท้ายสุดหลัง push ได้ผลแล้วแก้ที่พัง commit แต่ไม่ push แล้วหยุดรอพี่กัน
- Playwright โหลดแล้ว ใช้กับระบบจำลองหน้าโปรแกรม ยกเว้นกฎเบราว์เซอร์ไม่มีหน้าต่างเฉพาะงานเทสนี้ (พี่กันสั่ง *"ยกเว้นไว้เรื่องเทสนี้ เพราะมันใช้ภาพเยอะ"*)

- หน้าตาและการทำงานต้องเหมือนเดิม ห้ามแก้ข้อความ สี ระยะ หรือพฤติกรรมระหว่างจัดโครง
